# ADR-0002：原生 iOS 本地存储策略

## 状态

已接受，2026-08-14。

## 背景

原生 iOS 首版需要在没有账户、业务服务器和云同步的前提下保存一个选房任务、房源、费用、条件、看房记录和本地照片。当前聚合数据量小，主要访问方式是一次读取和整体保存；Web 版 IndexedDB 数据暂不要求自动迁移。

## 备选方案

1. SwiftData：适合多实体查询和持续演进，但首版需要拆分关系模型并提前承担迁移复杂度。
2. Core Data：成熟但样板和模型维护成本高于当前需求。
3. 版本化 Codable JSON 与独立媒体文件：实现直接、易测试、易导出，但不适合大规模查询。

## 决定

原生 iOS 首版使用版本化 Codable JSON 保存业务状态：

- `state-v1.json` 原子写入 Application Support 的 App 专属目录；
- 照片以独立文件保存在同目录的 `Media/`，JSON 只记录媒体 ID；
- 导出报告重新从结构化状态生成，默认不读取或嵌入原始图片；
- 状态保存失败时保留当前会话并向用户展示错误，不静默宣称已保存。

## 影响

- 不引入生产依赖，也不需要数据库 schema。
- App 卸载后本地数据会被系统删除；当前无跨设备恢复。
- Web IndexedDB 与原生 JSON 互相独立，不自动同步。
- 当产品需要多任务查询、云同步或复杂迁移时，应新增 ADR 评估 SwiftData，并提供从 `state-v1.json` 的显式迁移路径。

## 验证

- XCTest 覆盖 JSON 编解码往返。
- 状态文件使用 `.atomic` 写入。
- 报告测试确认不包含媒体字段。
