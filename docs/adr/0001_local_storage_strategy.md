# ADR-0001：本地存储策略

## 状态

已接受（Web 验证原型）。

## 日期

2026-08-09

## 背景

Web 验证原型没有账户、云同步或业务服务器，但需要保存结构化选房数据、房源截图和少量看房照片。数据不得被自动发送到开发者后台；浏览器数据被清理后允许丢失，但必须提前告知用户并提供不含原始图片的结果导出。

## 决策驱动因素

- 支持结构化对象与图片 `Blob`。
- 所有业务数据留在当前浏览器设备。
- 无多设备同步，无账户恢复。
- 支持明确的数据版本号和后续升级入口。
- 存储失败或 OCR 失败不能阻断手动录入。

## 备选方案

- `localStorage`：实现简单，但容量和 `Blob` 支持不足，不选。
- IndexedDB：浏览器原生支持结构化对象和 `Blob`，不增加生产存储依赖，选择。
- Dexie：API 更友好，但当前模型和事务很小，不值得增加依赖。
- 远程数据库：与无业务服务器和隐私约束冲突，不选。

## 决策

Web 验证原型使用单个版本化 IndexedDB 数据库 `rental-comparison-local`：

- `state` store 保存版本化 `AppState`，当前版本为 `1`；
- `media` store 以随机 ID 保存截图和看房照片 `Blob`；
- 应用不读取浏览器账户、位置或其他站点数据；
- 本地 OCR 只读取用户主动选择的图片，建议经用户确认后才进入字段；
- 决策报告和测试摘要不包含原始图片；
- 首次使用和结果导出附近明确提示“数据仅保存在当前设备”。

## 影响

- 优点：满足无服务器、本地图片、渐进录入和离线数据整理需要。
- 代价：无法跨设备同步，浏览器清理数据后无法恢复；iOS Safari 的站点存储策略仍可能导致数据丢失。
- 后续：数据模型升级时递增数据库版本并补充迁移测试；原生 iPhone 版本需要单独 ADR，不直接沿用浏览器实现。

## 验证方式

- 单元测试覆盖费用未知项、状态不变量和隐私摘要。
- Chrome 与 WebKit 端到端测试覆盖手动新增、比较、最终确认、撤回、淘汰和恢复。
- 真实 iPhone Safari 的长期存储保留时间尚未验证，应在用户测试中记录。
