# SPEC-001：选房决策核心流程

## 文档状态

- 状态：已确认
- 最近更新：2026-08-09
- 关联范围：[MVP 范围](../product/mvp_scope.md)
- 适用阶段：手机 Web 验证原型

## 背景

租房者需要从多个来源整理候选房源，并在信息不完整、费用口径不一致和看房记忆容易混淆的情况下完成选择。本规格定义从创建选房任务到确认最终房源的最小可观察行为，不规定具体前端技术或持久化框架。

## 目标

- 支持用户用真实房源完成候选录入、横向比较和最终选择。
- 保持成本公式、硬性冲突和未知信息透明。
- 支持整租与合租在同一候选池中按同口径信息比较。
- 确保所有房源内容默认只保存在当前设备。
- 允许最终选择撤回，避免把正常的反复决策建模成不可逆终态。

## 当前 Web 实现状态

### 已实现，核心流程已有自动化验证

- 创建或继续当前唯一选房任务；新建任务前提示当前本地任务会被替换。
- 用名称、城市、租赁方式、月租和居室数保存方案；在同一表单展开补充栏后，可保存地址、位置、空间、租约、费用和看房信息，并可绑定多张本地房源照片。
- 可运行本地 OCR；可识别字段作为可编辑建议填入，识别失败时降级为手动填写。
- 计算押金、周期性费用、一次性费用、月均居住成本和首期现金；未知费用不按 `0` 处理。
- 配置条件重要性、记录单套方案结果，并比较硬性冲突和未知项。
- 选择 2～5 套方案比较、切换基准并将基准固定在最左侧。
- 记录看房清单；检查项使用未检查、无问题、有问题，且仅有问题时提供可选文字和最多 3 张本地照片。
- 标记重点考虑、填写可选淘汰原因、淘汰与恢复方案、确认唯一最终房源并撤回。
- 在最终结果中展示关键成本、风险、未知项、看房异常和淘汰方案，导出无原始图片的 HTML 报告。
- 在本地生成匿名测试摘要和反馈草稿；没有业务服务器或自动埋点。

### 尚未完整实现

- 地区模板和面积单位当前固定为中国大陆和平方米；货币可自由填写，但不同货币比较尚不可操作。
- 方案详情已提供楼层、居室数和通勤方式的编辑入口；来源链接仍未提供编辑入口，也未记录任务与方案的创建、更新时间。
- 费用明细使用房源货币，支持每日、每月、每季度、每半年、每年和一次性周期；单笔费用的独立货币尚未实现。
- 通勤记录单程时间、单次支出和地铁、步行或开车方式；每月通勤天数和月通勤支出估算尚未实现。
- 比较页目前提供成本、通勤、条件和看房 4 组；位置、空间与租约条件尚未形成独立比较分组。
- 最终确认会列出费用未知、硬性条件风险和已记录看房异常，但尚未单独汇总所有“未检查”的看房项目。
- 反馈截图会在本地保存并二次确认，但导出的反馈 JSON 只记录“已确认附图”，不会把图片打包为实际附件。
- 真实 iPhone Safari 的图片选择、中文输入、导出和长期 IndexedDB 保留表现仍需真机验证。

这些差距是后续实现清单，不改变本规格定义的目标行为。

## 核心术语

- **选房任务**：一次具有明确城市和决策目标的租房选择过程。
- **租赁方案**：用户实际比较的对象，可以是整套住宅或合租中的独立卧室。
- **候选**：仍可参与比较的租赁方案状态。
- **已淘汰**：暂不参与主要比较、但可以恢复的租赁方案状态。
- **重点考虑**：可应用于多套候选方案的标记，不是状态，也不代表最终选择。
- **基准房源**：横向比较时固定在最左侧的参照方案，不代表产品推荐。
- **最终房源**：当前选房任务中由用户唯一确认的租赁方案。

## 前置条件

- 用户使用受支持的手机浏览器打开 Web 原型。
- 用户理解房源数据只保存在当前设备，清除浏览器数据或更换设备可能导致数据丢失。
- 用户至少拥有 1 套真实租赁方案；进入比较前至少需要 2 套候选方案。

## 主流程

### 1. 创建选房任务

1. 用户创建选房任务。
2. 用户填写城市、地区模板、默认货币和面积单位。
3. 用户可以填写预计居住月数、基础条件和主要通勤目的地，也可以稍后补充。
4. 系统将该任务设置为当前唯一进行中的任务。

### 2. 添加租赁方案

1. 用户选择手动添加，或绑定本地房源截图。
2. 用户填写自定义名称、城市、整租或合租、月租和货币。
3. 用户可在同一页面展开补充信息，使用浏览器定位、地图搜索或选点确认地址，也可以手动填写。
   打开地图后，地图瓦片、搜索和地址匹配会连接 OpenStreetMap 服务；不打开地图时不发起此类请求。
4. 系统允许保存其他字段仍为未知的方案。
5. 使用本地 OCR 时，可识别字段先作为待确认、可编辑的建议。
6. 用户确认或修改后，字段才成为已确认信息并参与计算。

### 3. 渐进补充条件

1. 用户可以将条件标记为硬性条件、普通偏好或不关注。
2. 用户针对单套方案记录符合、不符合或未知。
3. 系统不要求用户在首次添加方案前完成完整偏好问卷。
4. 用户淘汰方案时可以填写淘汰原因，但原因不是强制字段。

### 4. 计算费用

1. 用户以结构化明细记录每笔费用。
2. 系统按已确认信息计算首期现金压力：

   `可退押金 + 不可退一次性费用`

3. 系统按已确认信息计算月均居住成本：

   `月租 + 固定月费 + 不可退一次性费用 ÷ 预计居住月数`

4. 可退押金不计入月均居住成本。
5. 每日、每月、每季度、每半年和每年费用按月均折算；付款周期只影响现金支付节奏，不改变月均租金。
6. 预计居住月数优先采用用户输入，其次采用租约期限；两者均未知时，不计算一次性费用摊销结果。
7. 结果必须同时展示已使用的费用和未填写的费用类别。

### 5. 记录通勤

1. 用户记录一个主要通勤目的地。
2. 单套方案可以记录出行方式、单程通勤时间、单程费用和每月预计通勤天数。
3. 系统可以估算月通勤支出。
4. 通勤支出与月均居住成本分开显示，不自动合并。
5. 首版不自动调用地图服务获取或刷新路线。

### 6. 横向比较

1. 当至少存在 2 套候选方案时，用户可以进入比较。
2. 用户一次可以选择 2～5 套方案。
3. 用户可以指定一套基准房源；未指定时默认采用最先勾选的方案。
4. 基准房源固定在最左侧，用户可以随时更换。
5. 手机屏幕重点展示 2～3 套方案，并通过横向滑动查看其余方案。
6. 比较按成本、位置与通勤、空间、租约条件、偏好和看房证据分组。
7. 系统突出硬性冲突、差异和未知项，不生成综合分数或赢家。
8. 整租面积与合租私人空间面积必须带有范围标签，不自动比较大小。
9. 不同货币的金额默认不可直接比较；首版不自动换算汇率。

### 7. 记录看房结果

1. 用户打开某套方案的看房清单。
2. 每项默认是未检查。
3. 用户可以改为无问题或有问题。
4. 只有有问题时才展开文字和本地照片入口。
5. 用户可以隐藏模板项目或创建自定义检查项。

### 8. 调整候选判断

1. 用户可以为多套候选方案添加或移除重点考虑标记。
2. 用户可以将候选方案设置为已淘汰。
3. 已淘汰方案退出默认比较选择，但仍可查看。
4. 用户可以将已淘汰方案恢复为候选。
5. 如果基准房源被淘汰或移出本次比较，系统要求用户选择新基准，或使用当前最先勾选的候选方案。

### 9. 确认最终房源

1. 用户从候选方案中确认唯一最终房源。
2. 确认前，系统集中展示未确认费用、硬性条件冲突和未检查的关键风险。
3. 用户确认已经知晓未解决项后，可以继续完成选择。
4. 用户可以填写最终选择理由。
5. 系统生成决策结果页，并将选房任务设置为已完成。

### 10. 撤回最终房源

1. 用户可以重新打开已完成的选房任务。
2. 用户选择“撤回最终选择”后，原最终房源回到候选状态。
3. 系统清除当前唯一最终房源引用，并将选房任务恢复为进行中。
4. 原方案仍可保留重点考虑标记，并可以继续参与比较。
5. 用户可以重新选择原方案，也可以确认另一套最终房源。
6. 本地变化记录保留每次确认和撤回的时间及对象，不包含后台同步。

### 11. 导出与反馈

1. 用户可以导出适合阅读和分享的决策报告。
2. 报告默认不包含原始截图和看房照片。
3. 用户可以提交文字反馈、问题类型和随机测试编号。
4. 系统不自动附带当前页面、租赁方案字段或本地图片。
5. 用户主动选择附加截图时，必须再次确认。

## 数据要求

### 选房任务

- 城市、地区模板、默认货币、面积单位；
- 预计居住月数、基础条件、主要通勤目的地；
- 进行中或已完成的任务状态；
- 唯一最终房源引用；
- 本地创建和更新时间。

### 租赁方案

- 自定义名称、城市、整租或合租、月租、货币；
- 地址、来源链接、本地截图；
- 整套面积或私人空间面积及其单位；
- 户型、楼层、电梯、可入住日期、租期和付款周期；
- 费用明细、条件结果、通勤信息和看房记录；
- 候选或已淘汰状态、重点考虑标记；
- 本地创建和更新时间。

### 费用明细

- 名称、金额和房源货币；
- 每日、每月、每季度、每半年、每年或一次性周期；
- 是否可退；
- 是否已确认。

### 决策变化记录

- 变化类型；
- 关联租赁方案；
- 本地发生时间；
- 可选原因。

## 异常与边界场景

- 只有 1 套候选时，系统允许编辑但不能进入横向比较。
- 候选超过 5 套时，用户必须选择其中 2～5 套进行一次比较。
- 全部方案被淘汰时，任务保持进行中，并提示恢复或添加候选。
- 费用信息不完整时，系统展示部分结果和缺失警告，不伪造总额。
- 方案货币不同且没有手动换算值时，金额标记为不可直接比较。
- 面积范围不同或未知时，不对面积进行优劣高亮。
- 基准房源退出比较时，系统重新确定基准，不保留无效引用。
- 最终房源被撤回后，不得继续显示任务已完成或保留旧的最终房源引用。
- 定位权限被拒绝、地图搜索不可用或网络不可用时，用户仍可手动填写地址；用户清除浏览器存储后，系统无法从业务服务器恢复数据。
- 本地 OCR 失败时，用户仍可完成手动录入。
- 导出失败不得影响本地选房任务和最终选择。

## 交互要求

- 主导航只包含候选、对比和条件。
- 房源详情、看房记录和最终结果使用二级页面。
- 未知项、硬性冲突和费用缺失必须具有不同且可理解的呈现方式，不能只依赖颜色区分。
- “基准房源”不得使用“推荐”“最佳”等暗示系统结论的文案。
- “重点考虑”不得使用“已选定”等暗示最终完成的文案。
- 撤回最终房源属于正常可逆操作，不使用危险或惩罚性提示。
- 本地存储限制应在首次使用和导出入口附近清晰说明。

## 验收标准

- [x] 用户能够创建并继续一个选房任务。
- [x] 用户仅填写 5 个必填字段即可保存租赁方案。
- [x] 本地 OCR 建议未经确认不会参与比较或成本计算。
- [x] 至少 2 套候选时可以比较，单次选择上限为 5 套。
- [x] 基准房源可以更换，且不被表现为系统推荐。
- [x] 未知费用不会按 `0` 参与计算。
- [x] 可退押金不会进入月均居住成本。
- [x] 通勤支出与住房成本分开显示。
- [x] 整租面积和私人空间面积不会被直接判定优劣。
- [x] 硬性条件冲突和未知项在比较中可见。
- [x] 用户可以标记多套重点考虑方案。
- [x] 用户可以淘汰和恢复租赁方案。
- [x] 每次选房任务只能存在一套最终房源。
- [x] 用户可以撤回最终房源并恢复比较，任务状态同步回到进行中。
- [x] 用户可以导出不含原始图片的决策报告。
- [x] 用户内容不会在正常流程中写入产品业务服务器。

以上勾选表示代码检查与现有自动化已经确认核心可观察行为，不表示每个验收项都有独立测试，也不表示“尚未完整实现”中的字段和真机验证已经完成。

## 非目标

- 账户、登录、云同步和多设备恢复；
- 多人协作和共同评分；
- 远程生成式 AI 与任意链接自动解析；
- 自动地图路线、语音记录和综合评分；
- 支付、订阅、租后移交和其他地区模板；
- 正式 Web、Android 或 iPad 产品。

## 开放问题

下列问题不改变已确认的产品行为，但必须在对应阶段前解决：

- IndexedDB 后续数据版本迁移与完整本地备份格式；
- 真实 iPhone Safari 的最低支持版本、图片与文件导出兼容性及长期存储表现；
- Web 原型的测试托管平台、访问域名和用户数据清理说明；
- 原生 iPhone 阶段的最低系统版本、持久化框架和隐私声明。
