# 房源页亲和视觉重构

## 1. 任务目标

参考用户提供的多抓鱼 App 截图，以其温暖留白、手账感插画、粗黑文字、低饱和米色/绿色点缀和轻量分组方式，重构 iOS App 的房源首页视觉。保留租房决策的信息层级、真实交互和无障碍语义，不复制任何品牌、插画、商标或图标。

完成后，房源页应从默认 SwiftUI 列表感转为亲和、可信、可扫读的候选房源体验，并通过 Simulator 自动化回归。

## 2. 当前状态

- 首页由 `ListingsView.swift` 的 `ListingsView`、`NextActionCard` 和 `ListingCard` 组成。
- 全局入口在 `RootView.swift`，目前以系统默认 TabView 外观为主。
- 图片使用现有房源实拍和 `ListingImageView` 的 16:9 fill 裁切；业务模型、存储和交互均已稳定。
- 已有 UI 测试覆盖房源卡片、对比开关、详情导航、看房与快速添加。

## 3. 目标状态

- 米白底色、墨黑文字、深苔绿色作为操作与选中强调色，橙红仅用于待确认风险。
- 首页采用“任务标题 → 下一步 → 候选卡片”的强层级，减少浮夸阴影与系统感边框。
- 房源卡片用轻纸张感分组、实拍大图、手账式状态标记和清晰的双操作按钮；图片固定 16:9。
- 全局底部导航改为更有辨识度的亲和型图标与标签组合，但保持 3 个既有 Tab 的功能和无障碍标识。
- 不修改数据模型、迁移、业务规则、媒体存储或既有核心用户流。

## 4. 范围边界

### 本次包括

- 重构房源首页、下一步卡片、房源候选卡片和 3 Tab 导航的视觉样式。
- 新增少量可复用的 SwiftUI 颜色、字体、圆角和状态样式 token。
- 保持候选卡片点击、对比开关、详情跳转、快速添加与看房路径可用。
- 运行 iPhone 16e Simulator 的完整 XCTest/XCUITest；创建中文 commit 和 PR。

### 本次不包括

- 复刻多抓鱼品牌、吉祥物、插画、Logo、图标或文案。
- 改动比较页、待确认页、详情页的信息架构。
- 改动数据模型、网络、存储、权限和业务决策规则。

## 8. 新发现与意外情况

- 发现：首次渲染把候选数显示为字符串插值字面量。
- 影响：候选区的状态标签错误，属于可见 P2 问题。
- 处理方式：修复 `ListingsView` 的插值后重新构建、回归和截图，最终显示“3 套”。

## 9. 决策记录

### Decision：仅借鉴产品气质，不复制品牌资产

选择：使用米白、墨色、苔绿、轻分组与手账式状态语言，全部图标继续采用 SF Symbols。

原因：保留亲和性与辨识度，同时避免复制参考产品的商标、猫咪插画和专属视觉资产。

影响：本次不引入外部品牌插画或新生产依赖。

## 11. 风险与回滚

- 风险：首页布局调整可能导致小屏裁切或 UI 测试定位失效。
- 缓解：保留 accessibility identifier 和既有业务动作，使用 Dynamic Type 友好的 SwiftUI 布局。
- 回滚：本次改动仅在独立分支；可撤回视觉相关提交，不影响数据文件和业务状态。
