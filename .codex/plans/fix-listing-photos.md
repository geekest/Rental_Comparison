# 修复房源详情照片录入与展示

## 目标

- 将房源详情页轮播照片和图片管理网格约束在稳定的固定范围内，避免图片互相覆盖。
- 恢复右上角添加按钮的可点击区域，并允许连续追加照片。
- 避免横向翻页时因页面内容尺寸未受约束而产生重复照片的视觉残影。

## 定位结论

- `ListingMediaImage` 只使用 `scaledToFill` 和 `clipped`，自身没有从父容器获得明确尺寸；在 `TabView` 和 `LazyVGrid` 中，原图尺寸会参与布局，造成页面越界、控件遮挡及翻页重叠。
- 添加逻辑已通过 `AppStore.addListingMedia` 追加证据；问题集中在展示层尺寸和点击命中区域，不需要修改数据模型或存储策略。
- 照片导入后当前选择会被清空，可支持再次选择；需要避免空选择再次触发无意义的导入。

## 风险与取舍

- 采用局部 SwiftUI 布局修复，不调整照片数据结构和持久化逻辑，降低回归风险。
- 图片继续使用 `scaledToFill`，会裁切超出画框的部分，但符合现有封面式展示行为。

## 结果复盘

- 轮播页和管理网格内的图片都通过 `GeometryReader` 获得父容器的明确宽高，并在边界内裁切，避免原图尺寸撑开页面或互相覆盖。
- 右上角添加按钮增加明确的圆形命中区域和更高层级，避免被轮播图片挡住。
- 两处照片导入均忽略清空选择产生的空数组事件，保留清空选择以支持后续继续追加。
- `swiftc -frontend -parse Rental_Comparison/ListingImageView.swift` 与 `git diff --check` 通过。
- iOS 构建未执行：当前 Linux 容器没有 `xcodebuild`，需要在 macOS/Xcode 环境补充验证真机或模拟器上的选图及横向滑动交互。
