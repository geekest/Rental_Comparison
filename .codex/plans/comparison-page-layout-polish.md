# 对比页布局与信息层级修复

## 1. 任务目标

修复对比页当前的视觉和布局问题：分析区缺少横向留白、详细数据仍使用特殊按钮、置顶房源头部与详细数据列未对齐、详细数据排序靠后，以及导航标题滚动后不可见。

完成后，用户可以在统一留白和列网格下浏览置顶房源与详细数据，使用一致的标题展开控件切换两类信息，并始终看到“比较房源”导航标题。

## 2. 当前状态

- 主要实现位于 `Rental_Comparison/ComparisonView.swift`。
- 房源头部通过 `safeAreaInset(edge: .top)` 固定在导航栏下方，但导航标题仍使用默认显示模式。
- “对比分析”已经是 `DisclosureGroup`，但标题行没有横向内边距。
- “详细数据”仍通过独立按钮控制，且内容位于分析区之后。
- 房源头部使用宽度 `180`、间距 `16`，详细数据列使用内容宽度 `220` 加水平 `padding`，两套网格不一致。
- 相关 UI 回归位于 `Rental_ComparisonUITests/RentalComparisonUITests.swift`。
- 当前工作树已有用户原先产生的 `UserInterfaceState.xcuserstate` 未提交改动，必须保留。

## 3. 目标状态

- 两个信息区域均使用 `DisclosureGroup`，标题具备统一的系统展开/收起语义。
- “详细数据”在页面结构上位于“对比分析”之前，并保留独立展开状态。
- 分析标题行与详细数据标题行具有一致的横向留白。
- 置顶头部和详细数据采用相同的列宽、列间距和起始内边距；横向滚动仍保持联动。
- 导航标题使用 inline 显示模式，在页面顶部和向下滚动后均保持可见。
- 继续兼容 iOS 17，不引入新依赖，不修改数据模型和持久化逻辑。

## 8. 新发现与意外情况

- 发现：当前工程 scheme 未挂载 UI Test Target。
  - 影响：不能直接使用当前工程执行 UI 测试。
  - 处理方式：沿用前一轮验证方式，使用 `project.yml` 生成临时工程测试，不改写当前工程文件。
- 发现：用户截图中的红色线框和箭头是视觉标注，不是需要写入界面的文案。
  - 影响：仅将其作为间距与对齐反馈。
  - 处理方式：不把标注内容加入产品 UI。
- 发现：SwiftUI 内部横向 `ScrollView` 的自定义无障碍标识不会稳定出现在 XCTest 层级中。
  - 影响：直接通过内部滚动容器标识执行横向手势会造成脆弱测试。
  - 处理方式：从真实可见的“真实成本”指标发起横向拖动，并用“通勤时间”指标位置变化验证整列联动。

## 9. 决策记录

### Decision：统一固定列网格

选择：使用共享的列宽和水平内边距常量，头部每个房源单元与详细数据每个房源单元占用相同总宽度，分隔线放在单元边界。

原因：仅调整图片宽度或间距无法保证多套房源横向滚动后的边界一致；共享网格能同时约束起点、列边界和滚动范围。

备选方案：分别微调头部和详细数据的 `frame`、`spacing` 与 `padding`；容易形成脆弱的视觉近似，后续新增房源或动态字体时仍可能错位。

影响：头部图片可能比当前略窄或略宽，但其列边界会与详细数据稳定一致。

### Decision：默认优先展示详细数据

选择：详细数据 DisclosureGroup 默认展开，并放在分析 DisclosureGroup 之前。

原因：用户明确表示部分用户更关心详情数据；让首屏先进入可比较的成本、通勤等数据，同时保留分析区独立折叠能力。

备选方案：维持详细数据默认收起；虽然改动更小，但页面首屏仍然优先呈现分析，不能充分响应本次信息层级反馈。

影响：首次进入对比页内容高度增加；用户可以分别收起详细数据或分析区。

## 11. 风险与回滚

- 统一列宽可能改变图片在窄屏上的可见尺寸；通过固定总列宽和内边距控制，风险局限于布局表现。
- 默认展示详细数据会增加首屏内容高度；折叠控件提供直接恢复紧凑视图的路径。
- inline 导航标题会改变导航栏标题的垂直位置，但能满足始终可见要求。
- 回滚可按文件差异恢复，不涉及数据迁移和持久化。
- 后续视觉反馈：主标题与展开内容间距不足，且页面边缘留白仍偏小。
  - 处理方式：统一使用 `24pt` 页面内边距，并为两个主标题下的内容增加 `16pt` 顶部间距；二级栏目不再叠加额外页面内边距，以保持同一内容起始线。
