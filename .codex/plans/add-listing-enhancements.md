# 完善添加房源流程

## 1. 任务目标

解决添加房源中位置录入、截图识别、费用录入和看房记录分散且不贴合实际的信息结构问题。完成后，用户可在主表单完成必填信息后原地展开补充内容，通过浏览器定位或地图选点记录地址，并以结构化费用和异常优先的看房清单保存房源。

## 2. 当前状态

- `web_version/src/Prototype.tsx` 在独立基础页与详情页中分别录入房源字段；费用、条件结果与看房清单在详情页。
- `web_version/src/domain.ts` 的费用只支持每月或一次性，货币沿用任务货币；看房结果使用旧枚举。
- `web_version/src/ocr.ts` 提供本地 OCR 文本提取，但字段建议覆盖有限。
- `web_version/src/storage.ts` 通过 IndexedDB 持久化任务和房源。
- `docs/product/mvp_scope.md` 与 `docs/specs/spec_001_core_flow.md` 尚把地图能力列为不包括，需按本次已确认用户需求同步更新。

## 3. 目标状态

- 添加房源基础表单保存后可原地展开补充栏，而非进入两个填写页面；展开栏底部提供保存按钮。
- 地址支持浏览器定位、地图搜索和选点；无定位权限或地图服务不可用时仍可手动编辑。
- OCR 将可稳定识别的名称、城市、地址、租金、货币、面积、户型、楼层、电梯、可入住日期、租期、付款周期、押金和常见费用映射为可编辑建议，不强制覆盖用户输入。
- 货币允许任意非空代码或符号；押金默认可退；其他费用支持名称、金额、每日/每月/每季度/每半年/每年/一次性周期。
- 不显示条件结果；看房入口和文案统一为“看房清单”，检查枚举为未检查、无问题、有问题，且仅有问题时显示可选备注和照片。

## 4. 范围边界

### 本次包括

- Web 原型的数据模型、保存兼容、录入 UI、OCR 映射、费用计算、看房清单与测试。
- 使用无需 API Key 的 OpenStreetMap/Nominatim 搜索与地图选点，及浏览器 Geolocation 定位。
- 更新受影响的产品范围和核心流程规格。

### 本次不包括

- 路线规划、通勤自动计算、地理编码结果的云同步或任何业务服务器。
- OCR 的远程模型与无法从文本可靠判断的字段。

## 5. 影响文件

- `web_version/src/domain.ts`：扩展费用周期、位置及看房枚举。
- `web_version/src/calculations.ts`：按周期折算费用。
- `web_version/src/ocr.ts`：生成结构化且可确认的字段建议。
- `web_version/src/storage.ts`：兼容旧本地数据。
- `web_version/src/Prototype.tsx`：添加与编辑体验、定位地图、费用和看房清单。
- `web_version/src/prototype.css`：新增表单和地图交互样式。
- `web_version/src/*.test.ts`、`web_version/tests/core-flow.spec.ts`：覆盖数据、计算与关键流程。
- `docs/product/mvp_scope.md`、`docs/specs/spec_001_core_flow.md`：反映已确认范围。

## 8. 新发现与意外情况

- 首次全量 `npm run test:runtime` 以默认 6 个 worker 运行时出现本地 Vite 服务 `127.0.0.1:4174` 的间歇性拒绝连接；降低至 3 个 worker 后，所有与本次改动相关的核心流程、OCR、视觉 QA 和移动运行时大部分测试正常，仍有一个既有键盘过渡测试超时。该测试不涉及本次改动的应用运行时文件，且受保护运行时完整性检查通过。

## 9. 决策记录

### Decision：地图能力实现边界

选择：浏览器 Geolocation 配合 OpenStreetMap 瓦片与 Nominatim 搜索，不加入地图 SDK 或生产依赖。

原因：满足搜索、定位和选点，同时符合静态本地原型与最小实现边界。

备选方案：接入付费地图 SDK；仅提供经纬度文本输入。

影响：网络不可用或 Nominatim 限流时降级为手动地址与坐标输入。

## 10. 验证计划

- `npm run test:unit`：领域、计算、OCR、报告单测通过。
- `npm run typecheck`、`npm run lint`、`npm run format:check`：静态质量通过。
- `npm run check:runtime`：受保护移动运行时未被改动。
- `npm run build`、`npm run test:sites`：可构建静态产物并满足部署检查。
- `npm run test:e2e`：关键房源添加、费用与看房流程通过。

## 11. 风险与回滚

- 风险：第三方地图搜索可用性、浏览器定位权限和旧 IndexedDB 数据结构不一致。
- 缓解：全部提供手动输入降级；读取时归一化旧字段；不存储外部服务凭据。
- 回滚：撤回本次代码和文档变更即可恢复此前本地表单与数据解释。

## 12. 结果复盘

- 添加房源已从“先保存再跳转详情”改为同一表单的渐进展开。定位、地图搜索/选点、OCR 可编辑建议、自由货币、押金和周期费用、看房清单都已持久化到本地。
- 新增领域、计算、OCR 与端到端覆盖；通过类型检查、单元测试、核心 E2E、lint、格式检查、构建与 Sites 检查。
- 未做真实 iPhone Safari、真实定位授权及外部地图服务可用性的人工验收；这些能力分别保留手动地址输入降级。
